# PPU 渲染流程参考

FC/NES 的 PPU 渲染每一帧需要 262 条扫描线（NTSC），其中 0-239 是可见扫描线，240 是未使用的后缓冲，241-261 是 VBlank 期间。

## 扫描线时序（NTSC）

| 扫描线 | 名称 | 说明 |
|--------|------|------|
| 0-239 | 可见扫描线 | 每条扫描线渲染 341 个像素（含 HBlank） |
| 240 | 未使用 | PPU 不渲染，进入空闲 |
| 241 | VBlank 开始 | 设置 $2002 的 bit 7（VBlank 标志） |
| 242-260 | VBlank 期间 | CPU 可执行逻辑，PPU 不渲染 |
| 261 | 预渲染扫描线 | 准备下一帧，不显示内容 |

## 每条扫描线的像素时序

每条扫描线 341 个 PPU 时钟（dot）：
- 0-255：可见像素（256 个）
- 256：Sprite 0 hit 检查
- 257-320：精灵评估（OAM 评估）
- 321-336：下一条扫描线的背景预取
- 337-340：未使用（或额外预取）

## 背景渲染（Background Rendering）

### 名称表（Nametable）

- 每个名称表 1KB，存储 32x30 个 Tile 索引
- FC 主机板载 2KB VRAM，可存储 2 个名称表
- 通过 $2000 的 bit 0-1 选择当前名称表基地址

### 属性表（Attribute Table）

- 每个名称表后跟 64 字节的属性表
- 每 2x2 个 Tile 块共享 2 位调色板选择
- 属性表每个字节控制 4x4 个 Tile（16x16 像素区域）

### 图案表（Pattern Table）

- 背景图案表基地址由 $2000 的 bit 4 选择（0=$0000, 1=$1000）
- 每个 Tile 8x8 像素，使用 2 bits per pixel
- 每个 Tile 占用 16 字节（平面 0: 8 字节，平面 1: 8 字节）

### 渲染步骤（每条扫描线）

1. **背景移位器填充**：从名称表、属性表、图案表读取数据
2. **像素输出**：根据精细滚动（fine X）选择输出像素
3. **精灵评估**：在当前扫描线上找出最多 8 个精灵

## 精灵渲染（Sprite Rendering）

### OAM（Object Attribute Memory）

- 64 个精灵，每个 4 字节，共 256 字节
- 格式：Y 位置、Tile 索引、属性、X 位置

### 精灵评估（Sprite Evaluation）

在每条扫描线的 257-320 阶段：
1. 检查所有 64 个精灵，找出 Y 位置在当前扫描线上的精灵
2. 最多保留 8 个精灵（超出的精灵不显示，并设置溢出标志）
3. 将选中的精灵数据加载到二级 OAM（sprite buffer）

### 精灵属性字节

| 位 | 说明 |
|----|------|
| 0-1 | 调色板（0-3，对应精灵调色板 $3F10-$3F1F） |
| 2-4 | 未使用 |
| 5 | 优先级（0=前景, 1=背景） |
| 6 | 水平翻转 |
| 7 | 垂直翻转 |

### 精灵大小

- 8x8：由 $2000 的 bit 2=0 选择
- 8x16：由 $2000 的 bit 2=1 选择（使用图案表的 bit 0 选择上半/下半）

## 调色板（Palette）

### 调色板内存映射

| 地址范围 | 说明 |
|----------|------|
| $3F00-$3F0F | 背景调色板（16 字节） |
| $3F10-$3F1F | 精灵调色板（镜像 $3F00-$3F0F） |

> 注意：$3F04/$3F08/$3F0C 和 $3F14/$3F18/$3F1C 是通用的背景色。

### 系统颜色

NES 有 64 种颜色（但实际只有 56 种可用，某些是镜像）。颜色值 0-63 对应 PPU 内部的颜色查找表。

## 渲染开关

- $2001 的 bit 3：背景显示开关
- $2001 的 bit 4：精灵显示开关
- 在可见扫描线 0-239 的 1-255 像素期间，可以安全写入 $2006/$2007 修改 VRAM
